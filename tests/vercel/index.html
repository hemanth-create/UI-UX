Postgres that lives where your users do.

Halyard replicates a single logical database across 18 regions and routes every read to the closest healthy replica. Writes stay strongly consistent. You keep the same connection string.

Read path

Latency is a routing problem, not a caching problem.

Every replica runs the full schema. The router picks by measured round-trip, not by static region mapping, so a cold failover costs you milliseconds instead of a page.

p50 read

7ms

Measured from the application pod to the nearest replica, across all 18 regions, over the last 30 days.

Failover

1.4s

Median promotion time when a primary goes unreachable. Connections are held open and replayed, not dropped.

Consistency

Strict

Writes commit through a single primary with synchronous quorum. Read-your-writes holds without session pinning.

Fleet

Eighteen regions, one connection string.

Add a region and the router picks it up on the next health sweep. No client change, no redeploy.
